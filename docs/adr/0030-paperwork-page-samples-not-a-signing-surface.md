# ADR-0030 · 合伙人文件进 app 走「样本资料页」，不做同意面、不做签署流

日期：2026-07-28 · 状态：Accepted · 拍板：Danny（partner-docs-0728 盘问 · 两轮 8 项）

## 背景

合伙人交来五份文件（`D:\Boyle\avery`）：《保密协议 NDA》《个人信息委托处理协议 DPA》
《Avery 个人信息处理规则（隐私政策）》三份法律草案 v0.1，以及《Avery 标准管理信息填写
表单》（docx + pdf，共 7 张表）。诉求是「都放到 app 中，可以预览、可以用、可以下载」。

盘问先厘清了一件事：**这不是一类东西，是三件事。**

- 《隐私政策》读者是**员工本人**，且它自己写着「您点击『同意』并注册账户，即表示您已
  阅读、理解并同意本规则的全部内容」——它预设产品里有一个同意面。
- 《NDA》《DPA》读者是**客户公司**，甲方是客户、乙方是我方，末尾都是「双方盖章」
  「一式两份」「自双方盖章之日起生效」。这是销售阶段的纸质合同，不是 app 内的用户动作。
- 7 张表是**产品功能**：它回答首访者最常问的「我到底该传什么给 Avery」，而当时的空态
  答不上来。

盘问同时逼出三处文件与产品实况相反的表述：①存储地写「中华人民共和国境内」，实际后端在
法兰克福（[ADR-0024](0024-single-target-deploy-frankfurt-backend-supersedes-dual-deploy.md)
三地分布）；②「姓名与工号的对照关系由甲方保管，不得向乙方提供」，而产品整个建在姓名上
（`PersonIn.name` 必填、首字头像、检索）；③「不提供绩效评分…不生成任何形式的员工评分」
是绝对句，而这条红线 2026-07-13 已解禁成开关口径（`AVERY_ALLOW_PERSON_SCORING`，产品
文案 `upload.privacyNote` 早已改成「除非你们公司主动开启」）。

## 决策

**这一页是样本资料页，不是法律面。** 三条：

1. **不做同意面、不做签署流、不做勾选留痕。** 页面只提供在线预览 + 原件下载；签署走线下
   盖章，与文件自身「盖章生效」的约定一致。app 里点任何东西都不产生法律效力，页面明说。
2. **三处口径差不改文件、也不改产品**，改为一条常驻免责横幅 + 每份文件的草案徽章：
   「样本文本，非最终版本；实际条款以双方签署版本为准」。
3. **法律样本与填写表单的可见性分开**：表单挂真入口（上传面板、顶栏设置菜单、onboarding
   上传步），因为它是产品功能；法律样本同页但语气与分区不同，整页不挂顶栏 tab。

### Danny 的原话（决策依据，不是转述）

> averylite 现在没有生产功能，更像 preview，这些文件只用于与公司深入合作以后才讨论，
> 现在都为样本。

也就是说：拿一年后要签的合同去校准今天的 preview，是把未来的承诺当成今天的陈述。三处
口径差**到那一步再谈**——那时条款要重谈、【】要填、律师要过，产品形态也早不是今天这样。

## 为什么一个未来的读者会觉得奇怪

因为 app 里躺着三份法律文件，却：**没有任何同意面**（隐私政策自己要求了一个）、
**不挂顶栏 tab**（九个屏都有，它没有）、**存储地写着境内而生产在德国**。三处看代码都
解释不了，只能靠这份 ADR。

## 备选与否决理由

- **全量上线当正式文本** —— 否决。隐私政策首行明写「未经执业律师审核不得对外发布」，
  等于替公司作出未经审核的法律承诺，且其中至少一条与实况相反。
- **接真电子签（e签宝 / 法大大）** —— 否决。需要企业实名 + 第三方账号 + 费用，是一条独立
  产品线，不是收尾线能装下的；且当前没有「客户公司」这个身份可签。
- **做 app 内「我已阅读并同意」勾选** —— 否决。对 NDA/DPA 无法律效力，反而让人误以为签过了。
- **产品迁回境内以追平 DPA** —— 否决（推翻 ADR-0024 的重活），理由见上：现在谈太早。
- **7 张表全做成 app 内结构化表单** —— 否决。数据库只有 `person/project/signal/playbook`
  四类 entity，03/05/06/07 要新建 3–4 类 + 迁移 + 5 套表单 UI，是独立战役。当前做法是
  「下载空白表 → 线下填 → 走现有上传口」，零后端改动，且逐张标注 Avery 现在吃到哪一层。

## 后果

- `/paperwork` 是**唯一一条 element 不是 `<ScreenView />` 的路由**，且不在 `LiteScreen`
  联合类型里。顶栏当时已有 9 个 tab 且正在因窄屏溢出被另一条线修，加第十个是往那个 bug 上撞。
- 该页上**整个弹层家族不挂载**（详情浮层 / onboarding 闸门 / 草稿框 / 悬浮问 Avery）。
  真机逮到的：闸门对没有 contextId 的访客一律弹出，而 onboarding 里那条链接是新标签页
  打开的——新标签是全新会话，闸门又盖一次，用户点了链接看到的还是闸门。
- **起草者内部批注默认隐藏**。草案里夹着写给自己人的话（DPA 第三条后「谈判中甲方可能要求
  乙方承担脱敏义务，需谨慎权衡」是我方谈判底牌），默认显示的话，哪天把这一页转给客户看
  就当场念出去了。开关默认关、且不落 localStorage——「上次开过」不该成为下次的地雷。
- 文件正文**两种语言下都是中文**，只有页面外壳走 i18n。英文界面下如实说一句
  「文件只有中文」，不假装存在英文版协议（翻译法律文本 = 制造第二份要维护的承诺）。
- `verify-zh-purity` 新增 `/paperwork` 采样（此前该页对所有门隐形），并把
  `DPA/NDA/KB/TLS` 收进拉丁白名单——只收真专名，同批的 `App`→「产品」、`HR`→「人事」
  是改文案解决的，没有放宽门去迁就能改好的中文。
