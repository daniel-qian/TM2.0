# Ask 卡：员工自述式快问的红线边界（问事不问人 / 证据不进人卡 / 永不跨人比分）

> **状态:** Accepted（Danny 拍板 2026-07-13，grill 会话记录见 [.issues/ask-card-0713/PRD.md](../../.issues/ask-card-0713/PRD.md)）
> 红线本体不变（[ADR-0015](0015-product-tone-human-advisor-debrand-saas-naming.md)/[ADR-0018](0018-renqingwei-demoted-to-redline-product-truth-decision-layer.md)、`eval-harness/redline_rules.md` 冻结集）；本 ADR 只回答"一个字面上叫 1~5 打分的功能如何不撞红线"，为 Ask 表面立边界。

## 背景

融资团队点名要一个功能：manager 问"A 能不能负责跟乙方谈价"，Avery 生成快问链接分享到企微/钉钉/飞书/Slack/Teams，员工点 1~5 或 是/否 快答回传。锋利处：**答案是数字，且关于某个员工的处境**——一步走歪就是"Avery 给 A 打了 3 分"，正面撞上冻结红线"never quantifies, scores, diagnoses, ranks, or labels a person"。

同时有两个既有事实支撑"能做"：① 红线门本身是**认人不认事**的设计（`redline_rules.md` §scoring patterns：主语是 work/team/artifact 时抑制）；② lite 建议卡已有 `confidence.level`（Avery 对自己判断的信心）先例——"信心刻度"挂对主语就合法。

还有一个新暴露的口子：红线门只检查 **Avery 生成的文本**；员工点按钮回传的裸数字完全绕过文本门。所以边界必须是**结构性机器闸**，不是文案纪律。

## 决策

允许做 Ask（员工自述式快问），因为**问的是"事"、说的是"本人"**——员工自评对某件事的把握，不是 Avery 评判这个人。三条不可破的边界：

1. **问句问事不问人。**"你对这次谈判有多少把握"✅；"你觉得自己的谈判能力几分"❌。agent 生成的问句、manager 手改的问句，**保存前一律过服务端红线门**（`redline.validate`，EN+ZH），违规拒存并说明——没有绕过门的文本能出门，不管谁写的。
2. **答案是情境证据，不是人的属性。**回执落库挂在 Thread/问题上，**永不写进 `PersonEntity`、永不出现在人卡上、不进 Avery 笔记的人条目**。结构性保证：`LitePerson`/`PersonEntity` 无数字字段的既有护栏原样生效，Ask 回执在类型层就没有可挂到人身上的槽位。
3. **呈现永不跨人比分。**单人 = 原话 + 数字，标注"本人自述"；多人同题 = **不做每人一行的分数表**，只做定性汇总（"5 人中 3 人有信心，2 人提出价格权限顾虑"）。Avery 对回执的转述/汇总照过同一红线门。

配套透明性（红线②"不让被讨论的人觉得被处理"的正面版）：员工侧页面必须明写**谁在问、问的什么事、回答会原样给谁看**——员工自报、员工知情，是这个功能站得住的道德地基。

## 取舍

- **为什么不干脆禁数字**（只许定性选项）：杀死"10 秒快答"的产品价值，且这个数字是员工**自己的声音**、说的是**这件事**——红线守的是"Avery/manager 给人下量化判决"，不是"员工不许说自己有几成把握"。
- **为什么不允许挂人展示**（"A：3/5"人卡徽章）：触发 `PERSON-SCORE`，违反冻结规则集；且多人场景必然滑向排行榜——那是"never keeping score"品牌承诺的反面。
- **为什么边界是结构闸不是审查**：员工回传数字绕过文本门（新口子），唯一可靠的防线是**类型层无处可挂 + 表面机器断言**（DOM 无跨人分数表、人卡零数字），与 ADR-0022"边界是机器闸不是纪律"同构。

## 后果

- Ask 表面的 done 判定新增机器断言：问句红线门真拦 crafted 违规问句；回执不出现在人卡/PersonEntity；多人视图 DOM 无每人一行分数表；员工页透明三要素（谁问/问什么/给谁看）在 DOM。
- Avery 把回执织进建议/笔记时，走既有 EN+ZH 红线门，无新机制（与 lite-v1 PRD"笔记写侧过门"同一条纪律）。
- `CONTEXT.md` 新增 **Ask** 术语（surface：EN "Quick ask" / ZH "快问"；avoid：survey/问卷、poll/投票、打分）。
