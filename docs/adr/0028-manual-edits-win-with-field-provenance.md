# ADR-0028 · 真 CRUD：手编赢 + 逐字段出处（provenance）

日期：2026-07-22 · 状态：Accepted · 拍板：Danny（满态对齐盘问 · 决策批②）

## 背景

lite2 一直是**从上传文件只读派生**的世界：界面上每个字段都能溯源到某份文档，`null` 读作
「文档未提及」（absent≠none）。满态对齐战役拍板做**真 CRUD（范围：项目+人员）**——
「添加项目/编辑/归档」不再是引导或禁用位，而是真写。这立刻产生一个此前不存在的问题：
**手动编辑的值和文档说的值冲突时，谁算数？**

具体场景（盘问原题）：陈静的项目被 manager 手动把进度改成 60%，下周再传的周报里写
「进度大约一半」——界面显谁？

## 决策

**手编赢 + 逐字段出处标注。**

1. 每个可编辑字段带出处（provenance）：`document`（哪份文件）或 `manual`（手动改过）。
2. 手编过的字段，后续文档重新上传/重抽取**不覆盖**。
3. 文档新值与手编值对不上时，**不静默、不覆盖，冒一条提示**——语法复用「多看一眼」
   的 claim-vs-evidence 对照（「文件里的说法」vs「你手动改的」），由人裁断。
4. absent≠none 语义保留：手编也可以留空，留空仍显「未提及」，绝不折算成 0/默认。

## 备选与否决理由

- **文档为王**（新文档一到手编即被覆盖）：实现最简，但用户改过的东西会凭空消失——
  演示中当场改完再传文件就穿帮；真用户更不可接受。否决。
- **分字段分家**（进度/里程碑归手编、证据引文归文档，互不覆盖）：职责清晰但规则
  记不住，用户需要背「哪些能改哪些不能」。否决——出处标注让同一套规则覆盖所有字段。

## 影响

- 数据模型：项目/人员逐字段挂 provenance；后端新开写端点（`POST /team/{ctx}/notes`
  是既有先例，扩展同模式）。
- 「多看一眼」获得新差距来源：手编 vs 文档，与既有「自报 vs 信号」同屏同语法。
- 可追溯红线不破：任何字段都答得出「这个值从哪来」。
