# 满态对齐战役 PRD（rich-align-0722）

> 定稿依据：2026-07-22 盘问共识 1-12（一字不偏离）+ 后端/前端/门影响面/语料/她方部件规格五路只读摸底。
> 皮对齐（cr-align 35/35）已收官，本战役不返工皮，只补"满态观感的实"。
> 红线基调：ADR-0028（手编赢+逐字段出处）、ADR-0029（禁 demo 注入/UI 写死）、人面数字=开关口径（07-21 解禁，四层加固开关化，绝不回抄"永不打分"绝对句）。

## Problem Statement —— 用户（Danny，拿着产品去演示/对外的人）视角的问题

并排开我方（averylite lite2）与她方（cr-live）时，皮已经一致，但**观感丰富度差一个量级**：她方项目卡有进度条、里程碑圆点串、风险徽章、环形进度详情、成员负载/情绪、可筛选的团队目录、方法库网格、添加/编辑/归档全套操作；我方同一屏只有定性文案与收起的空槽。观众不会去读"诚实降级"的哲学——他们只会把稀疏读成"半成品"。

同时 Danny 的演示流程本身缺三样硬能力：一键进满态（现 seed 只有 2 份最小机制语料，铸出来还是薄的）、一键复位（一场演示结束无法 10 秒清场进下一场）、账号归属实证（观众问"数据是谁的、换个号还在吗"时只能口头解释）。

而补丰富度的路径受红线约束：不许 demo 注入、不许 UI 写死、人面数字默认零且解禁必须走开关+口径+出处。也就是说，问题不是"画得更满"，而是**让真管道产得出满态**——数据模型、抽取器、语料、CRUD、演示控制一条链全要通。

## Solution —— 用户视角的解法（一段话+要点）

给富字段（进度/里程碑/风险徽章、开关口径下的成员负载/情绪自述）开通"文档→抽取→payload→渲染"的真管道，配一套原创三亚酒店富语料（16 人/6 项目/SOP 全写满），让「示例团队」一键铸出与她方并排不输的满态；再补上项目与人员的真 CRUD（手编赢+逐字段出处+冲突提示）、team 屏目录形态、SOP 方法卡网格、设置里「重新开始」与真登录归属演示——每一处丰富都能当场点开出处自证，每一处文档没写的地方照旧诚实收起。

- 富字段走真管道：文档写了就抽、没写该行收起（absent≠none）；语法在本 PRD 定稿，语料与抽取器同稿共测。
- 人面数字开关化：开关开→负载/情绪显示且必带口径+出处（如"本人自述"）；开关关→人面零数字。四层加固改为两世界执法，横向比较结构两世界均禁。
- 真 CRUD（项目+人员）：添加/编辑/归档走新写端点（notes 端点为鉴权/红线先例）；手编赢，文档再传不覆盖，对不上冒"多看一眼"提示。
- team 屏两形态：空态=上传主位；有数据=她方目录形态（筛选 chip+3 列成员卡）+小补传入口。
- 方法库：三亚 SOP 抽成 2 列方法卡网格；非 demo 空态维持 coming-soon 诚实标；方法库无 CRUD。
- 演示控制闭环：示例团队一键满态、重新开始一键清场、真登录 claim 归属+切号隔离。

## User Stories

**经理（真用户）**

1. 作为经理，我要项目卡上直接看到进度条与百分比，以便不点开详情就掌握各项目推进程度。
2. 作为经理，我要项目卡上的里程碑圆点串（名称+状态色点），以便一眼看出每个项目卡在哪一步。
3. 作为经理，我要项目卡带风险徽章（等级+原因），以便先处理高风险项目。
4. 作为经理，我要点开项目详情看到环形进度、里程碑清单与分段总览条，以便向上汇报时有完整依据。
5. 作为经理，我要文档里没写的字段整行收起而不是显示 0 或默认值，以便确信看到的每个数字都出自文档（absent≠none）。
6. 作为经理，我要手动添加项目（标题/负责人/状态/截止等），以便文档还没写好时也能先把盘子搭起来。
7. 作为经理，我要在详情浮层里编辑项目字段并看到"手动编辑"的逐字段出处标注，以便分得清哪些是我改的、哪些来自哪份文档。
8. 作为经理，我要归档做完或停掉的项目并能从折叠区恢复，以便主网格只留活跃项目且不怕误操作。
9. 作为经理，我要重新上传文档时手编字段不被覆盖，以便我的现场修正不被旧文档冲掉。
10. 作为经理，我要文档值与手编值对不上时冒出"多看一眼"式提示（引用文档真句），以便核对是文档旧了还是我改错了。
11. 作为经理，我要 team 屏有数据时变成目录形态（筛选 chip+3 列成员卡），以便在十几人里快速定位某个组的人。
12. 作为经理，我要目录态仍保留小的补传入口，以便随手补文档而不用回空态。
13. 作为经理，我要手动添加/编辑/停用成员并能恢复停用者，以便花名册小变动不必重做整份文档。
14. 作为经理，我要方法库里看到从 SOP 文档抽出来的方法卡（2 列网格），以便新人照卡执行标准动作。
15. 作为经理（开关开的公司），我要成员卡显示负载/情绪且必带口径与出处（如"《本周周报》记录的本人自述"——系统可自证式措辞），以便参考时知道数字是谁说的、从哪来。
16. 作为经理（开关关的公司），我要人面零数字的界面，以便团队确信工具默认不背着任何人打分。
17. 作为经理，我要抽取质量降级时看到诚实标签（如 heuristic/degraded），以便知道该多核对一分。

**演示者（Danny）**

18. 作为演示者，我要并排开两边时观感一样丰富，以便观众不把我方读成半成品。
19. 作为演示者，我要「示例团队」一键进三亚满态，以便 30 秒内展示满态而不用现场传九份文档。

23. 作为演示者，我要所有富字段都走真管道（文档写了才有），以便被追问时能当场打开源文档指给观众看。
24. 作为演示者，我要真客户文档薄时界面诚实收起而非编造，以便演示承诺与真实使用完全一致。

**被展示的观众**

26. 作为被展示的观众（潜在客户），我要看到"实时数据缺位"这类诚实边界标注，以便知道产品现在能做什么、不能做什么。

**被讨论的员工（红线视角）**

30. 作为被讨论的员工，我要任何界面（开关开也一样）都不出现人与人横向比较的分数表/排行榜，以便负载情绪自述不会变成排名工具。

## Implementation Decisions

🔴 本节不写具体文件路径（会过期），只写模块名/端点形状/schema 形状/交互决策。

### A. 数据模型与抽取管道（共识 2、3；ADR-0029）

**A1. 项目实体加槽**：milestones 列表（每项 `{name, status}`，status 归一词表 done/active/blocked/upcoming；词表外→other 并保留状态原文供回显）+ risk 对象（`{level: high|medium|low, reason}`）。缺席不发键——payload 投影层沿用"None/空不发键"纪律，前端派生层沿用"optional 键缺席=文档未提及"口径，禁 `?? 默认`。

**A2. 字段的文档书写语法（抽取器认什么，本节即定稿；heuristic 走行首锚定标签正则，中英双语，语料与抽取器同稿共测）**：

| 字段 | 语法（行首锚定） | 归一规则 |
|---|---|---|
| 进度 | `进度：58%` / `完成度：58%`（沿用既有正则） | 仅收 0–100 有限数，0 合法；超界拒收不 clamp 成假值 |
| 风险 | `风险：高/雨季无备选场地`（等级/原因，`/` 或 `——` 分隔；原因可省） | 等级词表 高\|中\|低 + high\|medium\|low；词表外整行不抽。⚠️ 正则须与既有 `风险点：`（→blockers）区分：长标签优先匹配，`风险：` 全匹配锚定 |
| 里程碑 | 标签行 `里程碑：` 后连续列表行 `- 名称（状态）` | 状态词表 已完成→done、进行中→active、受阻→blocked、未开始→upcoming（+英文同义）；词表外走真 other：独立 other 点样式（非 upcoming 同款灰），照原样回显文档用词（与 status 的 other 同哲学——不替客户文档改写措辞） |
| 负载/情绪自述 | 周报"人员动态"段内 `- 小王｜负载自述：85%｜情绪自述：吃紧` | 只认带 `自述` 后缀的标签（口径=本人自述，出处=所在文档名）；无"自述"字样的人身数字一律不抽。情绪词表 如常\|偏紧\|吃紧（映射定性枚举）；负载仅收 0–100 |

LLM 抽取路径的 prompt schema 同步加同一套槽位，解析后仍过抽取红线门；两路抽出的形状必须一致（合约测试考）。

**A3. 人身数字的存储与红线（本战役最要紧的设计决策）**：抽取层**永远抽取**自述行，落入 person 实体的专用 `self_report` 子对象（形状 `{load?: {value, caliber, source}, mood?: {value, caliber, source}}`，caliber+source 为必填），红线门只放行此槽——散落在 person 上的自由数字键仍然全禁（既有禁键表语义不变，等于把"合法数字只能活在自述槽"写进结构）。**payload 投影层按开关决定发不发**：开关关→self_report 整个不投影，人面照旧零数字；开关开→投影并在 payload 顶层带 additive 键 `scoring_enabled: true`（仿 demo/account_linked 的缺席语义）。这样 demo 母本不必随开关重铸（母本内容寻址只看文件，开关只影响投影）。前端第③层运行时剥离改造为两世界：开关缺席/false→现行为（一切 number 键全丢）；true→仅放行 self_report 白名单，且渲染处强制带口径+出处标记元素。第④层渲染纪律同步改为开关口径注释，不回抄绝对句。**残余风险明文承认**：文档通道的自述行作者身份不可验证（系统只能证明"某文档如此记录"，不能证明"本人真的这么说"）——因此口径措辞必须是系统可自证式（如「《本周周报》记录的本人自述」，而非直接断言「本人自述」）；这条不对称（CRUD 手填硬 422 vs 文档通道不可验作者）进收官验收表单让 Danny 签认。

**A4. 抽取健壮性硬约束（语料侧同守）**：同一人名跨文档逐字一致才聚卡（CJK 聚卡教训）；打分/排名文字触发抽取红线即整包拒铸；花名册表格行（姓名/职位/部门/司龄/负责列）是 16 人唯一真值源。

### B. 真 CRUD：项目+人员（共识 4、5；ADR-0028）

**B1. 端点形状**（照 notes 写端点先例：owner_token 或账号二选一鉴权、失败一律同体 404 无枚举、Pydantic 校验、写侧红线门、ValueError→422）：

- `POST /team/{ctx}/projects`（添加）、`PATCH /team/{ctx}/projects/{id}`（编辑）、`POST /team/{ctx}/projects/{id}/archive` 与 `/restore`（归档/恢复）
- `POST /team/{ctx}/people`、`PATCH /team/{ctx}/people/{id}`、`POST /team/{ctx}/people/{id}/archive` 与 `/restore`
- 归档=软删标记，可逆；**不做物理删除**（销毁类动作人工闸哲学延伸到产品语义）。
- registry 双实现（内存/Postgres）duck-typed 同 API 扩展，合约测试同扩；Postgres 侧实体整体 JSON 存储，无需 DDL。

**B2. 逐字段出处模型（ADR-0028）**：实体字段级 provenance `{value, origin: doc|manual, source: 文件名或"手动编辑", updated_at}`。手编置 origin=manual；文档再 ingest 时 **manual 字段不覆盖**；doc 抽出值 ≠ manual 现值时生成 conflict 记录（claim=手编值，evidence=文档原句逐字引用），前端复用"多看一眼"claim-vs-evidence 语法冒提示，提示只引真句、显示值与判据值分开。

**B3. 写侧红线**：person 写入过禁键表校验；**CRUD 不开放人身数字编辑**——负载/情绪只能由带"自述"口径的文档产生，经理手填他人负载/情绪=替人打分，直接 422。项目字段全量可编辑。

**B4. 交互落位（对齐她方形态，文本零抄）**：添加项目/成员=页头右端 primary 按钮展开内联表单（label 全中文 aria）；**编辑/归档只在详情浮层页脚操作区**（编辑态原地变输入框，保存 primary+取消 ghost），卡面不放操作控件——避免整卡即按钮的嵌套交互问题；停用成员=卡右下低调文字键+页尾"已停用"折叠区（灰化+恢复键）。详情浮层由只读升级为"只读+页脚操作"，出场动画快照机制对编辑态单独处理。所有新按钮挂既有按钮家族类。

### C. team 屏两形态（共识 6）

空态=上传主位（现状不动）。有数据=她方目录形态：筛选 chip 行（组别一组恒在；情绪一组**仅开关开时渲染**）+ 3 列成员卡网格 + 小补传入口。成员卡解剖对齐她方结构（头像/姓名/职位·组别/focus 行/底部信息格），底部格两世界：开关开=负载数字+情绪定性+口径出处角标；开关关=定性格或整格收起——**关世界定性格只许来自非 self_report 字段（focus/职责），情绪词表词与口径角标关世界零出现**。

**裁决：目录筛选 chip ≠ 横向比较结构**（07-22 校验裁决）。判定理由：ADR-0023 禁的是每人一行数值表/排序榜/跨人分数并列；按自述定性状态筛选不产生跨人分数并列。落实约束：① 情绪 chip 行挂「按本人自述筛选」口径角标；② 筛选结果视图禁排序/禁计分徽章（组别计数徽章可，情绪计数徽章不可）。**上传部件降位不卸载**（两分支都渲染，门与产品语义都依赖）；成员卡保留既有 DOM 类名锚点。

### D. 方法库（共识 7）

数据通道：payload 新增 optional `playbooks` 键或独立只读端点（`GET /team/{ctx}/playbooks`），缺席=无方法卡，前端判空降级。SOP 文档语法定稿：`## 方法：标题` 小节 + `适用：…` + `要点：` 列表 + `标签：a、b、c` → 方法卡 `{title, description, tags[]}`。满态渲染=2 列网格方法卡（方形渐变图标+标题+描述+chips 结构对齐她方）；onboarding 勾选槽位升级为真卡时**保留每个所选 id 一个带槽位 data 属性的元素及 tag 类名锚点**。非 demo 空态维持 coming-soon 诚实标。**方法库无 CRUD**。

### E. 演示控制（共识 8、9）

**E1. 重新开始**：设置齿轮菜单加第三行。行为=**清 lite2:\* localStorage 全量**（照共识原文：含 context 锚点、known contexts、onboard 态、flow 待办、语言/观感偏好一并回出厂）+ 遗忘全部 owner_token + 回 onboarding 闸门。store 层新增全量重开 action（现只有 run 级 reset）。按钮过家族类+中文 aria；改齿轮菜单结构须同步既有门。

**E2. 示例团队换三亚满态**：seed 目录内容换成三亚 pack（env 指向新目录即可，**零代码**）；母本内容寻址自动重铸；能力探测门（有语料才露门）与 claim 克隆隔离机制不动。生产为 LLM 铸造分钟级，部署后手动 claim 一次暖场。

**E3. 账号环节**：演示流程=真登录→claim 数据归账号→切号验证隔离（未登录 401、claim 失败同体 404 无枚举，均为既有语义）。本地 mock 缺 Supabase env 时登录入口按探测口径隐藏（现状），**账号环节在线上实例演**；若要本地演，须先补配 env 且确认前端登录面板已是"探后端能力"口径而非只看自身 env（历史坑）。

### F. 三亚语料 pack（共识 10）

9 份文档（花名册/公司概况/项目总览/本周周报/婚宴 BEO 纪要/管理规范与升级红线/旺季排班纪要/脱敏简历×2），16 人 6 项目，人名一律小王/小张式代号；富字段按 A2 语法**全写满**（6 项目各配进度/风险/里程碑；周报人员动态段写负载/情绪自述行）；SOP 3-6 份按 D 节语法写进管理规范文档。素材源=三亚调研目录（findings/pack-draft/脱敏 seed），她方 demo 文本零抄袭，原创成稿免审。硬约束：case 素材里故意越线的打分段绝不带入；≤15 份、单文件 ≤8MiB、格式在支持表内；跨文档人名逐字一致。

### G. 锁词/红线（共识 12，全程有效）

## Testing Decisions

纪律不变：**先落 spec 行与门，再写码**；spec 新行从 stick 6 起每棒一号（现表最大 stick=5，无 stick 1），门用 SPEC_STICK 分期照旧。以下按门影响面摸底列方向：

**T1. 人面数字两世界（最重的门改造）**：AFK 门的血条正则四处断言 + "人卡任意数字即红"断言改为两世界执法——开关关（读壳上开关标记）：现行零数字断言原样跑；开关开：数字只许出现在带口径+出处标记的元素内（如 data 属性锚点），元素外仍跑血条正则；**分数表/排行榜/横向对比结构两世界无条件禁**——「横向对比结构」机器判据边界：禁=每人一行数值表/排序榜/跨人分数并列；不禁=目录筛选 chip（见 C 节裁决）。两世界都要真栅栏：开关开考"必须带出处"，开关关考"一个数字都没有"。加断言：凡渲染 self_report（含情绪定性枚举词）的元素必须带 `data-metric-source` 锚点——情绪词表词出现在人卡且无锚点=红。p0 门的"0%"正则收窄到项目进度元素（否则负载恰 0% 的人误伤）。

**T2. 富字段 absent 世界**：status-truth 门 absent 分支照既有配方加克隆件（分别删 progress/里程碑/风险键），断言无依据的卡不渲染进度条与风险徽章（或渲染 absent 语义的"文档未提及"措辞），对照组真值卡照常渲染，判据吃 raw 键不吃渲染文案。缺 progress 的项目绝不能吐 "0%"（p0 门现有断言即栅栏）。

**T3. team 目录形态**：cr-alignment spec 新增 team 屏 stick 6 行（rect/count 探针照 stick 5 写法钉筛选 chip 行与 3 列网格）；status-truth 依赖的项目卡/状态点选择器锚点必须保活；AFK 门上传相位两分支都渲染上传部件（卸载=360s 假红）；成员卡 DOM 类名锚点保留。

**T4. 项目卡富部件**：spec 加 count 行钉徽章/进度条数量护栏 + prop 行钉徽章字重与色；新小字徽章过对比度硬门（AA 4.5）。

**T5. 方法卡网格**：slot tag 类名与槽位 data 属性集合相等断言保活（或同 commit 改 spec 行）；reopen onboarding 按钮恰 1 个；方法卡若为 button 须挂家族类或进白名单。

**T6. CRUD**：registry 双实现合约测试扩展（新写 API 全覆盖）；写侧红线单测（人身数字键拒写 422、自述槽仅文档通道可产生）；表单控件过 aria 中文门（弹层表单是静态走查盲区，红线仍要求全中文 aria）+ 按钮家族门 + 扫雷 D 系 selftest（默认样式控件/过小图标钮/无焦点反馈）；请求失败不得漏 console error（p0 门考）。改后端服务须重启进程再验。

**T7. 重新开始**：onboard-gate 门加世界 F：重启→骨架+闸门重弹+context 锚清空；switchers 门加重启世界，考"全清含语言/观感回出厂"这一拍板（非重启世界的记忆契约不变）。

**T8. 手编 vs 文档两世界**：手编后再传文档→手编值保持+conflict 提示冒出（引文档真句）；无冲突时不冒。提示语法与"多看一眼"同源纪律（claim 引真自述句）。

**T9. demo/真客户两世界**：三亚 seed 一键 claim→满态全字段断言（16 人/6 项目/里程碑/风险/SOP 卡都真渲染，聚卡数对）；薄文档（1-2 份真客户样例）→诚实降级断言（收起行为+extraction_mode 标签）。离线 AFK 门跑 heuristic 路径，语料必须 heuristic 可抽（A2 语法即保证）。

**T10. 像素基线**：team 4 张 + projects 4 张 + playbooks 4 张必重拍（9 屏×2 皮×2 视口共 36 张，只重拍改动屏，冻结屏不碰）；详情浮层若入基线另行加张。开关开/关两世界若造成同屏两形态，基线以开关关（默认世界）为准，开关开走断言不走像素。
