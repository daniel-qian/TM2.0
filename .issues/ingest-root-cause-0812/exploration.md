## 0 · 一句话诊断

**「字节保管」「理解（LLM 抽取）」「归并对账」三件责任被绑进了同一个同步 HTTP 请求**，
三个症状全部由这个绑定派生：

| 症状 | 机制（已钉死的病灶） |
|---|---|
| ① 卡住、永远转圈 | `transport.ts:1270` 的 `send()` 是裸 fetch——无超时、无 AbortController、无取消键。请求 118-224s，连接一断 UI 永远停在「正在读取文件…」。她第三个文件的请求**根本没到达后端**（后端全天零 4xx/5xx，Caddy 没开 access log，中间层是瞎的） |
| ①′ 更狠的暗伤：**首传断连 = 档案孤儿化** | `run_in_threadpool` 里的抽取不随断连停止——服务端做完、落库、把 `owner_token` 写进死 socket。**token 只回一次**，丢了 = 那份档案永远无人能打开。用户重试 = 再铸一份。库里 104 个 context 有多少是这么来的 |
| ② 越传越慢（118→163→224s） | **不是 LLM**。`pg_registry.py:401-447`：每次 `put()` 先 `DELETE` 该公司**全部**旧行再整表重插（entities/materials/memory_files/source_documents 四张表），第 N 次补传重写的是 1..N 批的总和。注释自认："re-put = replace: one atomic snapshot"。LLM 段成本只挂当批文件（`file_append.py:137` 只抽 fresh_docs） |
| ③ 逐个传数据更差（11 张 vs 18 张项目卡） | 三层叠加：(a) 抽取过抽——花名册「当前负责事项」列被抽成项目（提示词判据 "it gives that project its own owner" 在花名册形状上**本身失效**，每格确实有 owner=本行的人）；(b) **粒度闸只站在单批证据池边上**——`extract.py:1836` `apply_gate(out, docs)` 全仓唯一调用点，R1/R3/R4 三条折叠规则全部依赖跨文档证据，补传时 docs=单文件 → 三条同时瞎掉；(c) 近似标题不归并——`_project_key` 是精确尺，全仓无模糊匹配器 |
| ③′ 重试放大器 | 同字节重传**不被识别**：`_unique_parse_names` 按文件名改成 `xxx(1)` 接纳为新文档 → 再烧一遍 LLM → 材料块无去重重复入库（`file_append.py:155` 无条件 extend）→ 血缘虚增。`skipped_duplicates` 只守同请求并发竞态，"超时后手动重传"这个最常见场景永远打不到 |

**深模块答案**：把「档案」做成 deep module。接口收成两个动作——
`deposit(files) → 秒级回执`（字节保管 + 内容幂等 + 每文件状态）和 `observe() → 状态/实体`（轮询）。
**理解与对账变成档案的内部过程，seam 从「HTTP 请求边界」挪到「档案状态机」。**
这一刀同时杀掉 ①（保管不再被理解的分钟级延迟劫持）、①′（token 秒级到手）、
③ 的批次盲区（对账不再被请求作用域绑架，可以看全档案）。

## 1 · 分段方案（每段独立可上产，各杀一个症状）

### S0 · 便宜加固（不动架构，先止血）

1. **内容幂等（sha256）**——重试安全的地基，其他一切重试引导的前置。
   - 哈希在 `read_capped` 读完字节当场算（`ingest_api.py:348/823` 两个构造点），
     命中 `existing_content_hashes(ctx)` 就**连临时文件都不写**直接跳过（省 LLM + 省 parse）。
   - 迁移 = 简单增量列（照 0005 形状，**不需要** 0009 的 want/ADD 双清单——那是给可重放
     CHECK 的）：`ADD COLUMN IF NOT EXISTS content_sha256 text NOT NULL DEFAULT ''` +
     `pgcrypto`（🔴 必须 `WITH SCHEMA public`，0001:33-44 有生产事故碑）+ 库内 backfill
     `UPDATE ... digest(content,'sha256') WHERE content IS NOT NULL`。
   - 回执**新开字段** `skipped_identical`（带 matches_source_key），不复用 `skipped_duplicates`
     ——两者语义不同（"你这批里有重名" vs "库里已有一模一样的"），前端要能分开措辞。
   - 内存腿：`SourceDocument` 加字段即可，`put()` 是 dict 赋值自动随行。
   - pg 腿三处：INSERT 列清单、`_prior_src_hash` 平行回填临时表（同 content bytea 的坑）、
     `get()` 元数据 SELECT 带上（64 字节，无「拉全部字节」顾虑）。
2. **前端超时熔断**——照抄 `authStore.ts:120-129` 现成范式（AbortController+setTimeout）。
   🔴 **只熔断，不自动重试**：/ingest 每发新铸 context+token，自动重试=复刻「回车两下」数据丢失
   事故。补传的手动重试在 sha256 落地后才安全。/ingest 超时的文案要诚实：
   「可能已经传上了——刷新一次看看档案在不在，再决定重不重传」。
3. **后端分段计时日志**——五条线共同发现：全管线**零耗时埋点**（perf_counter 零命中），
   现在设计异步是摸黑设计。parse/LLM/归并/落库四段各打一行。
4. **Caddy 开 access log**——两行配置。0812 排查时中间层全瞎（「浏览器发没发出去」在服务器上
   无法回答）。**服务器配置改动，归 Danny 点头。**
5. 多选引导文案 + 「一次全选更快更准」——治标但零成本，顺手。

### S1 · seam 挪位：异步 deposit（根治 ① ①′）

采用侦查线 A1 的方案 C（三选一里唯一能诚实回答「容器重启任务丢了怎么办」的）：

- **pg 任务表 `ingest_jobs`**：收字节的同一事务里写 `queued` 行，秒级返回
  context_id+owner_token+job；进程内 worker 线程认领→`processing`→抽取→`done/failed`。
- **启动时孤儿回收**：扫「processing 但无人认领」→ 标 `failed: server restarted`。
  （`_BUILD_LOCK` 是纯内存锁的教训：重启即清零，卡死的任务态今天完全没有回收机制。）
- **`SourceDocument.status` 加 `'reading'` 中间态**——前端 `LiveFileStatus` 本来就是开放兜底
  （`transport.ts:563-580`，"缺席显示未知，绝不默认 ingested"），additive 安全。
- **前端契约不变是迁移成本的胜负手**（侦查线 A2 的核心发现）：
  `ingestStatus/appendStatus` 的 `'ingesting'→'ready'` 二值翻牌**对外不变**，轮询关在
  `uploadFiles/appendFiles` 内部，翻 `'ready'` 的判据 = 全部文件到达终态。
  这样 **~30 道活跃门 + 18 张数据态像素基线理论上零改动**（它们全锚在这个契约上），
  但必须整批重跑证明没有提前翻牌。🔴 每轮 poll 都要过 `stillOn` 身份复核（不是只在最后一次）。
  🔴 OnboardGate 防双击闸依赖「忙态覆盖整个耗时窗口」——轮询期间 busy 语义必须维持。
- 「请保持页面打开」这句文案随之退役——传完就走、回来看结果，正是增量上传场景要的能力。
- ⚠ 像素基线数量口径：实测 **18 张**（4 屏×2 皮×2 视口 + 手机专拍 2），spec 文件头注释写 14、
  票面口径 12，都落后了（#79 加 room 屏后没人更新）。顺手修注释。

### S2 · 增量归并质量（根治 ③）

按侦查线 A4 的对比表（三个选项全部零 LLM 花费）：

- **第一刀 = 选项 c（抽取侧结构判据）**：`apply_gate` 加 `R5-duty-column`——
  `doc_kind=="roster"` 且「该文档项目候选的 source 行号 ≥N% 与人的行号重合」→ 整体降级，
  parent 指向那一行的人。**文档局部判定 → 全选与逐传天然一致**，是唯一不依赖跨批证据池的防线，
  直击本次病灶。逃生口照抄 R3 guard(a)：自带 progress/dueDate/里程碑的不降。
  ⚠ 排除 `line:1`（模型给不出行号时 clamp 默认 1，会假重合）；
  ⚠ 启发式路 source 语义不同（span 起点非人行号），规则两路要各自定义或只对 LLM 路生效。
- **第二刀 = 选项 a（全档案重跑粒度闸）**：唯一让「一次全选 == 逐份补传」**结构性成立**的方案。
  作者那段「整表静默删除」的担忧（`file_append.py:133-136`）**保留为实现约束、不再作为方向否决**
  ——它写下时「字节可重建全量 docs」「卡的血缘可查」两个前提都不成立，#87 血缘落地后都成立了
  （`file_delete.py:35-51` 已立过同款「前提被 #87 更新」的碑）。三道锁缺一不可：
  ① 闸从「删」改「折叠」——降级必要条件 = parent 非空且在存量列表里，无 parent 的规则在补传路禁开火；
  ② 血缘完整性前置断言——任何待判卡的来源文档重建不出来 → 整个重判放弃，回执诚实记账；
  ③ 软折叠而非物理删——**产品拍板点：复用 `archived` 还是新开 `folded_into`**
  （`_absorb_project` 明写 archived 是经理手编领域，系统写会撞车）。
  另两笔账：裁决记录今天**不落库**（`pg_registry.py:336-338`，重启后答不出「为什么这张卡不见了」，
  而"说得出为什么"是粒度闸模块头立的唯一合法性根据）——补传路开火前必须先解决；
  重跑成本随档案线性涨（parse-only，CSV 秒级，大 PDF 不是）。
- **选项 b（标题包含整理征）降级为 a 的可选补充**：吃不到职责项病灶（无词面包含关系），
  且正对着 R3 guard(b) 那条「不许凭前缀编造母项目」的血泪碑。不单独上产。
- 🔴 **必须先补的门**：「同一份语料，一次全选 vs 逐份补传，项目卡数相等」端到端判据。
  现状：`apply_gate`/`build_milestone_index` 在全套测试里**从未被喂过一份以上的文档**
  （17 处调用全是单文档），跨文档维度结构性不可见——这就是它活到生产的原因。
  `test_file_append_t10.py` 49 条里 granularity 零命中。
- ⚠ A4 报告里「单文件 17 项目违反每文档 12 上限」的疑点**已由主线结案**：
  那次（ctx_8dd7789d5d78）是两文件一批（花名册+项目清单），17=两文档各≤12 去重后的和，无矛盾。

### S3 · 存储增量化（根治 ②）

`put()` 的 DELETE+全量重插改成增量写（embeddings 已经是增量先例，`pg_registry.py:278-308`）。
动 registry 契约（"re-put = replace" 是明写的设计选择），冲击面在 needs_db 套。
**可以和 S1 合票**：任务 worker 落抽取结果时天然是增量写点。单独做优先级最低——
在档案还小的现阶段它只是慢，不是错。

## 2 · 账号方案 A 彩排地图（并行线，与 S0-S3 无依赖）

**动线**（侦查线 A5，含从未被真跑过的步骤标注）：
Danny 后台建已确认账号 → 手动分发 → 经理登录（`signInWithPassword`，密码不经我们服务端）→
登录态上传自动绑定（`account_linked`，全方案唯一自动的一步）→ 换设备登录
`/account/contexts` 恢复（**方案存在的唯一理由，零真跑记录**）。

**彩排判据清单（9 条，用 avery-e2e+* 测试户）**：
① 登录态上传→`account_linked:true`；② `/account/contexts` 列出该 context 且无 header 时 401；
③ 清 localStorage 换设备→登录→`adoptContext` 恢复、数据对得上；④ 游客上传→登录→**手动点认领**→绑定；
⑤ 登出后 owner_token 腿仍 200（claim 是加法不是收权）；⑥ demo 全程免登录不受影响
（`demo.py:143,156` 签名零鉴权参数，已核）；⑦ 双账号切换不串场；⑧ 真 JWT 的 60s 缓存过期；
⑨ `autoRefreshToken` 续期后请求不 401（代码接对了但零测试覆盖）。

**必须 Danny 人手**：后台建号（第一次顺手验证「后台建的用户真跳过邮件确认」——这本身是未验假设）、
对外分发、密码轮换（产品内无自助改密入口）。
**测试账号归属**：0805 碑开放的是「用 avery-e2e+* **跑和清理**」，没说 agent 能不能**建**——
建议 Danny 预建一个交给 agent，最干净。

**产品缺口（彩排暴露的，开不开票归 Danny）**：
- `authGuestNote` 说「登录只是把数据存到你名下」——只在先登录后上传时为真；先上传后登录要
  **手动点认领**，刷新丢状态入口就消失且无提示。文案承诺 > 实现。
- 注册入口对预置账号用户是混淆源（点了会卡在邮件确认）。
- 无改密/重置入口，运维全靠 Supabase 后台。
