## 第一轮（形态）

| # | 决定 | 理由 |
|---|---|---|
| 1 | **内部草案通道**：DRAFT 水印 + 免责横幅，不当正式文本发布 | 隐私政策首行明写「未经执业律师审核不得对外发布」；放进 app = 对外发布 |
| 2 | **资料包：预览 + 下载，不签** | 文件自己约定「自双方盖章之日起生效」；app 里点任何东西不产生法律效力，做签署 UI 只会让人误以为签过了 |
| 3 | **表单：下载空白件 → 线下填 → 走现有上传口** | 上传管线已吃 .docx/.xlsx，零后端改动；做成 app 内结构化表单要新建 3–4 类 entity + 迁移，是独立战役 |
| 4 | **三处口径差都不改**（存储地 / 姓名 / 打分） | Danny 原话：「averylite 现在没有生产功能，更像 preview，这些文件只用于与公司深入合作以后才讨论，现在都为样本。」——拿一年后要签的合同校准今天的 preview，是把未来的承诺当成今天的陈述 |

第 4 项落地为一条零成本保险：常驻免责横幅「样本文本，非最终版本；实际条款以双方签署
版本为准」。既不改文件也不改产品，把三处口径差一次性提前免责。

## 第二轮（落地）

| # | 决定 | 理由 |
|---|---|---|
| 5 | **a/b 可见性拆开**：表单挂真入口，法律样本同页但不挂 tab | 表单是产品功能（首访者最常问「该传什么」），法律样本是给谈合作的人看的物料；两者读者、频次、紧要程度都不同 |
| 6 | **docx 原件 + 另做一套 xlsx** | docx 每张表都写「需要多条记录时请复制本页」——16 人要复制 16 次；xlsx 一表一 sheet、一行一记录，对填表人和对解析都是正确形状 |
| 7 | **正文转成页内 HTML 渲染**，原件另给下载 | docx 浏览器打不开；只有 PDF 内嵌的话手机上体验差、搜不了，且水印与草案横幅只能在 HTML 形态下做 |
| 8 | **一次性手工转 + 标版本日期** | 五份文件、季度级变更频率，建 docx→HTML 管线不值；漂了也一眼看得出来（每份卡片底部标「源件 v0.1（2026-07-27）· 转录于 2026-07-28」） |

追加（Danny 在开工前补的）：**a 类也要有入口**——上传面板、首页设置栏各指一处。
落地为三处入口（上传面板两条 / 顶栏设置菜单一条 / onboarding 上传步一条）。

## 盘问期间查出、当场改变了方案的事实

这些不是决定，是**事实**，但每一条都推翻了一个原本要做的东西：

1. **顶栏已经 9 个 tab 且正在因窄屏溢出被另一条线修**（`LiteTopbar.tsx` 的
   `uiux-narrow-0728` 段）。→ 这一页不做第十个 tab。
2. **app 没有登录墙**（auth 是可选的，访客全程能用）。→「内部通道」落不到登录后面，
   只能落成不挂入口的路径。
3. **数据库只有 `person/project/signal/playbook` 四类 entity**。→ 7 张表里只有 01/02
   有原生落点，其余 5 张只进材料库；这一条必须逐张写在页面上，否则用户填完一下午
   会判定「传失败了」。
4. **红线是整批硬拒，不是丢掉那一格**（`pipeline.py:130`）。→ 表 07 的警告必须写明
   后果：一格写了分数，同一发上传里的 01–06 全部作废。合伙人的 docx 只说了
   「本表不产生任何分数」，没说后果。
5. **表 02 的「已暂停」在项目状态词表里根本不存在**。→ 顺带修（见 feat-092）。
