### 几个当时拍的决定（后面的票别再推一遍）

1. **三个 transport 方法是可选的（`?:`）**。必填会让 `stubTransport` 当场编译不过；而且
   「stub 通道没有后端 → 整段不渲染」本来就是对的降级姿态（同 `fetchAdviseRuns` 先例）。
   **没有给 stub 写实现**：那要铸一条点了必 404 的假链接，正是「不建假按钮」所禁。
2. **防双击的闸在 store 不在 UI**。React 的 `disabled` 要等一次重渲染才落到 DOM，同一拍的
   第二次 click 在那之前；而这个端点**不幂等**——第二发不是一次多余请求，是每个人真的
   再收到一条新链接。
3. **铸链失败三分家，自有文案**。绝不复用 `transport.*` 通用句：`httpErrorMessage` 把
   **422 映射成「那个文件类型不接受」**（与 415 共用），一次人数越界会对着经理讲文件格式。
4. **周期取数据里最大的那个**（`YYYY-Www` 字典序即时间序），**不按本机时钟算「本周」**：
   服务端的 period 是铸链那刻定的（周五铸链、周一才填），前端再算一遍只会得出第二个真相。
5. **链接一律渲染服务端拼好的整条**。`public_base()` 只认 `AVERY_PUBLIC_BASE`、从不看请求头，
   前端自拼 `apiBase()+'/f/'+token` 在本机看着对、生产上公共域与 API base 是两个地址就错。
   ⚠ 本地起后端跑门时**必须**带 `AVERY_PUBLIC_BASE`，否则界面上是一条形状完美的**生产**链接。
6. **刻意不做**（不建假按钮）：模板编辑器（要一整个表单编辑器）· 重新入库按钮
   （`_submission_payload` 里**没有「这条归没归档」这个字段**，做出来没有诚实的标题也没有诚实的
   禁用态）· 逐人答案渲染（在资料库屏上摊开员工原话是另一个设计问题）。

### 🔴 高危 1 条：铸链途中换公司 → 生成键永久死掉

`createFormLinks` 两个 `stillOn` 早退都**没把 `formsBusy` 放回 `idle`** 就 `return false` 了，
而 `adoptContext` 的公司域清单当时只清三件、不含 `formsBusy`。唯一能清它的 `resetFormsWrite`
只挂在「切换模板」上，而那排按钮只在有 ≥2 张模板时渲染——今天恒是内置周报这一张。
所以：**经理点了「生成本期链接」，趁请求还在飞切到另一家公司 → 生成键在此后所有公司上
永久置灰、标着「正在生成…」，只有刷新页面或登出能救。**

最刺的一点：`resetLiteCompanyData` 里我自己写的注释**逐字点名了这个危险**
（「换账号时卡在 'minting' 等于把生成键永久置灰成一个死按钮」），却只把它应用到了登出那条路，
没应用到**远为常见**的换公司那条路。

修法：两个早退各自 `set({ formsBusy: 'idle' })`（进门那道 `formsBusy !== 'idle'` 闸保证同一时刻
只有一次铸链在飞，所以这样放开是安全的），并把 `formsBusy` / `formsError` 补进 `adoptContext`
与 `restoreSession`-404 两份清单。

**回归门 + born-red 验证**：`t3-story.mjs` 新增一节「铸链途中换公司」，把那一拍复现出来。
撤掉修复后**精确打红两条**（`busy=minting` / 切回来后生成键仍是死的），还原后 4 条全绿。
此前**没有任何门跑过这条路径**——门与故事各自都跑过铸链、也跑过换公司，就是没跑过

### `recipients[].id` 送错了，而且送错比不送更糟

后端那个 `id` 是**工号**（01 表人员ID → `FormSubmission.person_id`），T5 的 `PersonIndex`
拿它当身份尺。本票初版顺手送了 `team.people[].id`——那是 `team_cards()` 投的**人卡内部键**
（`registry._one_person_card` 的 `p.id`），工号（T5 新加的 `PersonEntity.person_id`）
**今天根本没投到前端来**。

`PersonIndex.resolve` 规则 2 原话：「工号对不上（或这条读数没工号）→ 退回姓名。**除非**双方
工号都非空且不同 —— 那是两个恰好同名的人」。于是一家**真填了工号**的公司：花名册那条是
`MKT-001`、表单这条是内部键 `pe_...`，两个都非空且不同 → 判成两个同名的人 → **连同一个人
都并不上**，自述整条回流不了。

机器判定（`t3-probe-staffnumber.py`，直接问身份尺，不赌 HTTP 也不赌解析器）：

```
花名册有工号 · 表单送 ''（本票现在）  → 并得上
花名册有工号 · 表单送内部键（初版）    → 并!不!上
花名册无工号 · 表单送 ''              → 并得上
花名册无工号 · 表单送内部键            → 并得上
```

修法：**不谎报工号**——送空串，归并退回按姓名，与 T5 之前一字不差。
代价如实继承 T5 交接那句：公司里有同名员工时，那一份自述会被**诚实跳过 + 记一行日志**，
不掷硬币挑一个。

复合链路已端到端验过（`probe-reflow`，本轮跑完即删，结论记在这里）：真界面选人 → 铸链 →
员工填完提交 → **周雅人卡上长出「本人自述：负载 72 / 情绪 stretched」，出处指向那份周报**，
且花名册那张卡没有被并成两张。
