## 逮到的三条

### 🔴 一、人卡上出现没人填过的「自述负载 0%·本人自述」（已修·已上产）

徐岚与马衡两张卡各有一条 `自述负载 0%`，出处指向 `项目总览.md:7` / `:16`——
那两行的原文是「负责人：徐岚」「负责人：马衡」，**一个数字都没有**。
马衡还多一条情绪自述，出处指向「参会：马衡、林小满（康乐部）」。

- **根因**：`llm_extract._SYSTEM` 白纸黑字要求「只有文档明确标了自述才准吐 self_report」，
  **模型不听**。而落地层 `_llm_self_report` 只做范围检查（0..100），`0` 合法所以照收。
  提示词管不住模型，判据却只写在提示词里——这就是洞。
- **修法**：按同文件 `_not_a_person` 的既有做法（"belt to the model's suspenders"）加**取证闸**：
  每条读数要在文档里找到一行同时含「名字 + 自述标记 + 这个值」的原文，找不到整条丢弃；
  找到就把 `source` 重指到**那一行**（比模型给的人物行更可核）。拿不到 doc 一律判否。
- **门**：`test_person_selfreport_switch_03.py` +4（编数字被丢 / 值对不上那一行也丢 /
  出处重指 / 情绪同理）。⚠ 原有那条「LLM 自述与启发式同形」的桩文档此前**靠模型说了算才绿**，
  已改成真把读数写在纸上——它正是这次事故的形状。

### 🟠 二、同名两位「林小满」被并成一张卡（已修·已上产）

花名册里 SY-0422（前厅部经理）与 SY-0906（康乐部主管）并成一张：team 取前厅部，
`owns` 里却挂着康乐部那位的活。

- **根因两层**：① schema 从没要过 `person_id`，模型自然不吐；
  ② `_build` 的**文档内**归并只按姓名（`_person_key`）——T5 把跨文档换成 `PersonIndex` 之后
  两条腿就分叉了，文档内先并掉，跨文档再讲究也来不及。
- **修法**：schema/提示词补 `person_id`（逐字，且落地时校验它**确实出现在文档里**，模型编不出来）
  + 文档内归并改用同一本 `PersonIndex`。
- **门**：`test_llm_extract.py` +3（分得开 / 编的工号不收 / 没工号时逐字退回老行为）。

### 🟠 三、幻影第三张卡 →「文档写了部门就不该算认不出」（已修·已上产）

修完第二条后，工号第一次真的进了生产索引，于是 T5 的**规则 3** 第一次被触发：
纪要里「参会：…林小满（前厅部）」没带工号 → 同名歧义 → 另开一格 →
团队页出现**第三张**林小满（无职位、前厅部），与真那位看起来一模一样。

- **判断**：那句话自己写了部门，两位候选里只有一位在前厅部。**这不是猜，是读。**
- **修法（规则 3.5）**：名字歧义 + 无工号 + 读数带非空部门时，若候选里**恰好一位**部门对得上
  就并进那位；对上两位（同名又同部门）或一位都对不上，立刻退回规则 3 的老口径。
  有二次判据就用，没有就不猜——绝不把「像谁」当成「是谁」。
- **门**：`test_llm_extract.py` +4（对得上就并 / 对不上另开 / 没部门另开 / 同名同部门不许当身份）。

`.hitl-session-round1.json` **没被 `.gitignore` 的旧写法覆盖**，随 `4d74ebd` 推上了**公开仓库**。

- **影响面**：仅 `ctx_b6613c806f72` 一个 context 的写权限（token 按 context 隔离，feat-038）。
  碰不到别的 context、账号体系、任何 API key。
- **处置**（Danny 当场拍板）：**把那个 context 删掉**——token 从此指向不存在的东西，等于吊销。
  已执行 `active_registry().delete()`，公网 `GET /team/ctx_b6613c806f72` → 404，
  库里 contexts/entities/source_documents/materials/form_submissions/form_templates 六张表全为 0 行。
  没有改写 git 历史：公开仓库的旧 blob 在 fork 与缓存里都可能留存，删 context 才是真吊销。
- **纪律**：忽略规则已收紧为 `.issues/**/.hitl-session*.json`（`0b4fcf4`）。
  ⚠ 更该记住的是：**凡是脚本会落盘的「会话/状态」文件，默认当凭据看待**——

## 补做：铸链绑项目 + 工号接进界面（同日，Danny 拍「按你的建议开工」）

第三条差距（员工写的原话进不了项目卡）与第二条的后半截（工号送不出去）其实是同一处：
**铸链界面拿不到它该送的两个字段**。一起补完。

**形态选择（为什么是逐人一格）**：一批人本来就可能各扛各的项目，
整批绑一个＝替经理断言；按负责人自动绑＝替经理决定这份周报在说什么。
所以是「选了谁，就为谁各挑一个」，默认**不绑**——绑了才会把员工原话写进项目卡，
猜错的代价是把 A 的话挂到 B 的项目上。

- 后端：`_one_person_card` 投 `person_id`（缺就不发键，absent≠none）。
- 前端：`LivePersonCard.person_id` → `LitePerson.personId` → 铸链**有工号送工号、没有仍送空串**
  （没工号的公司一字不差地退回旧行为）；`FormLinkRecipient.project_ref` 补进契约。
- 界面：选了人之后长出「这几份周报各自关于哪个项目」，逐人一行一个下拉（默认「不绑项目」）；
  「谁交了」那一行显示 `关于 <项目>`（没绑的不编一句「未绑定」）。
- 截图人眼过时**又逮到一处自己造的**：两位同名同事现在正确分成了两张卡，
  于是选人那排出现两个一模一样的「林小满」，经理不知道该点哪个 →
  重名时 chip 与收件人行补一段部门（不重名的不补，避免噪音；分隔符走 CSS 间距，
  不写任何标点字面量——那是本文件上游注释里立过的碑）。

**上产与生产复验**：镜像 `main-20260807-190332`（= main `99d83f7`），第四次 swap，流程同前。
生产复验走 `hitl-bind-prod-check.mjs`——**领一份示例团队**（`/demo/claim`，零抽取花费、
克隆是 ephemeral）而不是真上传：常驻表单段在场、没选人时绑项目那块不出现、
选了人长出下拉、默认「不绑项目」、线上 12 张项目卡全进了选项（13 = 12+1）。
示例花名册没有工号列，所以它顺带验到「没工号的公司这一格是**缺席**而不是空串」，
铸链据此退回按姓名认人——旧行为一字未动。用完的克隆已删。

**门**：新增 `hitl-bind-story.mjs`（浏览器层，zh/en 各一遍全绿）——
