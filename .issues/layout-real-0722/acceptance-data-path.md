# 验收数据通路（本战役验收手册的地基，2026-07-22 定）

## 问题

「示例团队」一键 demo 的语料是 `eval-harness/tests/fixtures/demo-seed/`，只有两份 md：
`员工花名册.md`（**2 人**：林晓梅、郑国豪）+ `本周周报.md`（**1 个项目**）。
它自己在文件里写明是「**机制语料**」——只为证明中文名不塌卡、克隆副本互不写脏，**不是展示语料**。

后果：进 demo 后主页右栏两个真部件面板都是**空态**——
- 「文件自己对不上的地方」→ 现在没有自相矛盾的地方。
- 「文件里反复提到的人」→ 现在文件没有特别指向某个人。

**只给 Danny 这条路径，他验不了「真部件」，只能验空态。**

## 🔴 不采取的做法

- ❌ **不新造展示语料塞进 demo-seed** —— 会同时污染 `tests/test_demo_claim.py` 的机制断言，
  且把「一键示例团队」做成一个内容更丰富的假数据源，逼近「零假数据」红线的边缘。
- ❌ **不为了让面板好看而编数据** —— 面板空就是空，空态本身就是要验收的诚实表现。

## ✅ 采取的做法：两段式人测路径（复用既有真语料）

### 第一段 —— 空态验收（走 demo 门）
新访客闸门页 → 「用一份示例团队先看看」→ 主页。
**看点**：双栏骨架在**空态下**是否仍然成立（右栏两面板显示诚实空态而不是塌掉/留白洞）、
KPI 五卡在小数字（2/1/2/1/0）下是否好看、`0 条待跟进` 是否老实显示 0。

### 第二段 —— 满态验收（走上传路径）
在同一会话里上传既有中文真语料（`eval-harness/tests/fixtures/cjk/`，**已 tracked，非新造**）：

| 文件 | 内容 | 喂出什么 |
|---|---|---|
| `Sanya_Team_Roster_ZH.md` | 三亚酒店花名册，**7 人**（陈思雨/李明轩/周雅婷/孙浩/吴桂芳/赵倩/Lin Qing），跨 5 个部门 | 人卡网格铺满、组别筛选有料 |
| `Sanya_Project_Weekly_ZH.md` | 2 个项目（销售 FAQ 梳理 = **有风险/阻塞**；客房夜床服务复核 = 正常推进），带自报进度与阻塞原文 | 项目卡四态、决策卡高风险、**差距面板的「自报」侧** |
| `Sanya_Ops_Handover_ZH.md` | 前厅交接备忘，**原样抄录同一条阻塞**并补「法务至今没有结论」 | **跨文档重复提及** → 「反复提到的人」面板（吴桂芳/赵倩 多文档出现）；**「观察」侧证据** |

**看点**：右栏两面板出真内容、差距卡的对照双列两侧都有真原文、KPI 计数跳到真数。

### 为什么这三份能同时喂出两个面板
- `Sanya_Ops_Handover_ZH.md` 是**故意**把周报的阻塞原样抄一遍再补一句现状的 —— 天然构成
  「自报 vs 后续观察」的两侧证据，正是她 `/gaps` 对照双列需要的形状。
- 吴桂芳（交接人）、赵倩（接班人、且在周报里承接返工）**跨两份文档出现** ——
  「反复提到的人」数的是**被提到次数**，这正是它的判据。

## 未决 / 待现场验证 ⚠️

- 上述「喂出什么」是**按语料内容推断的**，未实测。棒A 起手第一件事就是走一遍这条上传路径，
  实测两个面板到底出不出内容。**若不出**，说明 `gapDerive` / 反复提及派生的门槛比语料强度高，
  那就要把「面板在什么条件下才有内容」写进验收手册，而不是去改语料迁就面板。
- 上传路径吃的是 mock 后端（`AVERY_BRAIN=mock` + `heuristic` 抽取），
  与生产真 LLM 抽取结果不同 —— 验收手册要写明这一点，避免 Danny 把 mock 的抽取质量当成产品质量。
- ⚠️ 上传前必须确认 `window.__AVERY_BUILD__.apiBase` 指向 `127.0.0.1:8137`
  （AGENTS.md 血教训：跑过 `verify-bundle-privacy` 后 dist 会落回生产域名，
  再上传就是**往生产库写测试数据**）。本次已验：`apiBase = "(local default 127.0.0.1:8137)"`。
