### ① 「快问」这个名字和现有功能撞了 —— **需要你定**

你 kickoff 写「悬浮入口……叫「快问」」。但「快问」**已经是 feat-034 Ask 的正式名字**：
ADR-0023 把 surface 定死（EN "Quick ask" / ZH「快问」），en/zh 里 9+ 个键在用
（`ask.eyebrow`、通知「一条快问已拟好」、待办来源「来自快问」…），且这条锁在 M3 生成器的铁律里。

两个「快问」是两件不同的事：

| | feat-034 快问（已上线） | 你要的悬浮入口 |
|---|---|---|
| 把什么发给谁 | 把**链接发给员工**，员工自述 1–5 / 是否 | 把**问题发给 Avery**（LLM） |
| 结果在哪 | 回执收在 Ask 卡上 | 议事室的分析流 |
| 谁管着 | ADR-0023 三条红线 | 无材料 gate |

同屏两个「快问」，用户分不清自己在问谁。
**我的处置**：悬浮入口先按不冲突的命名做（走既有「去议事室」族 `homeDecisionAskRoom` /
`notesEmptyCta`）。改一个 label 是一行——你说了算，这是最便宜的反悔点。
（无论如何不能叫 Nexus：`verify-p0.mjs:265` 有硬闸扫 `Nexus/nexus/现实差距`。）

### 我自己逮到并修掉的两处（说明我怎么验的，你不用重复验）

1. **空态在 721–880px 宽（含 iPad 竖屏 768）左右内边距被清零**，骨架卡贴死屏幕边。
   是棒B 一条「防御性」媒体查询误伤空态（空态那个 div 同时挂两个类）。
   讽刺的是它自己的注释白纸黑字写着要防这件事，然后被上面 8 行的规则反手做掉。
   已修（选择器加 `:not(.lite-home-frame-empty)`），实测 721/768/800/880 全部回到 36px。
2. **「与顶栏逐像素齐平」在真浏览器上原本是假的**：headless 用的是覆盖式滚动条（0px），
   而 Windows Chrome 是经典滚动条（15px），内容盒偏左 7.5px，顶栏按真视口居中 → 差 7.5px。
   已修（`scrollbar-gutter: stable both-edges` 让内容盒重新与视口同心），
   **headed 和 headless 两种模式下 1600/1440/900 三个视口都验过，逐像素相等**。
