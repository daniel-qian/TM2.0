# 验收语料（人测用，**不是** 产品数据，**不是** 门的判别语料）

## 这是什么

给 Danny 人测右栏「文件自己对不上的地方」面板用的上传材料。
走**上传路径**进产品——和他自己拖一份公司文件进去**完全等价**。

## 为什么需要它

实测（`../panel-firing-truth.md`）：现有所有语料都喂不出**一张**差距卡。

差距卡的判据是「**嘴上说没事、身上挂着卡点**」：
`statusRaw ∈ {on-track, steady}` **且** `blockers.length ≥ 1`。
已经自报「有风险 / 阻塞」的项目**故意不算差距**——它的卡点和它自己的说法是一致的，不矛盾。

| 现有语料 | 为什么不出卡 |
|---|---|
| `demo-seed/本周周报.md` | 项目自报 `blocked`，且阻塞行落在 `## 待办` 段没归到项目块（blockers 抽出来是空的） |
| `cjk/Sanya_Project_Weekly_ZH.md` | 「销售 FAQ 梳理」自报**有风险**（一致，不算差距）；「客房夜床服务复核」自报正常但**没有阻塞行** |

→ 没有这份语料，Danny 只能看到一个永远空着的面板，验不了「真部件」。

## 🔴 它不是假数据

- 它**不进产品代码**，不进 `demo-seed`（那是 `test_demo_claim.py` 的机制语料，动它会同时破测试）。
- 它**不进门的判别语料**（`tests/fixtures/cjk/` 有「语料泄题」的教训）。
- 它只是**一份写得像真周报的 .md**，由人在验收时手动上传。
  产品里显示的每一个字都来自这份文件的原文——这正是产品的承诺。

## 语料内容的真实性来源

沿用 `eval-harness/tests/fixtures/cjk/Sanya_Team_Roster_ZH.md` 的**同一批人名与职位**
（陈思雨 / 李明轩 / 周雅婷 / 孙浩 / 吴桂芳 / 赵倩），这样上传后 owner 能真的挂到人身上，
「文件里反复提到的人」面板才有内容。

「自报正常推进、同块却写着卡点」是**真实周报里最常见的形态**——写周报的人习惯先给个乐观的状态，
再在下面老实交代卡在哪。这正是这个功能存在的理由，不是为了让面板好看而捏的形状。

## 怎么用

验收时在同一个会话里依次上传：
1. `eval-harness/tests/fixtures/cjk/Sanya_Team_Roster_ZH.md`（花名册，7 人）
2. `本周项目周报.md`（本目录，3 个项目）

预期（实测值，见 `../panel-firing-truth.md`）：
- 差距面板 **2 张卡**
- 关注成员面板 **3 行**
- KPI 计数跳到真数

⚠️ 上传前确认 `window.__AVERY_BUILD__.apiBase` 指向 `127.0.0.1:8137`
（跑过 `verify-bundle-privacy` 后 dist 会落回**生产域名**，再上传就是往生产库写数据）。
